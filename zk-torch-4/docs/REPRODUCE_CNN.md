# Reproduce the frozen CNN workload

Use `../repro/cnn/README.md` and its pinned requirements/provenance. In a fresh isolated environment, regenerate the public dataset/model locally with `python reproduce.py /tmp/morpheus-trained-cnn`; no dataset or model weights are vendored. The wrapper refuses an existing output directory and fails on hash mismatch. Floating training may differ by platform; do not search seeds or replace the model to match results.

From `zk-torch-4`, build `morpheus_trained_cnn` with CPU replay (`--no-default-features --features cpu-replay --bin morpheus_trained_cnn`) using the repository's existing MLP CPU build settings: CARGO_INCREMENTAL=0 and CARGO_PROFILE_DEV_DEBUG=0; profile.dev.package opt-level=3 for zk-torch-4, almost-goldilocks-cuda, keccak, sha3, num-bigint and num-integer; overflow checks ON and debug assertions ON. Use the locked dependencies and record the compiler version. The original CNN experiment used direct rustc with a frozen audited library. A subsequent standard Cargo CPU build from an initially empty target directory passed on all 482 unchanged source files, using locked locally cached dependency sources and rustc 1.99.1. This is not a clean-machine dependency-download test. The Cargo-built executable (SHA256 4e6b84c2b8b53d69a614fd912861c2e1fa4b98625cda07f555c6282459493541) then accepted the original frozen B1 wire using only its pinned public registry and passed all 12 isolated negative controls. Its source/build and verifier receipt hashes are in CNN_RESULTS.json. It is distinct from the original direct-rustc executable; original timings remain associated with that original binary. This closure checks reproducibility/correctness, not performance.

For each fresh output directory, set `RAYON_NUM_THREADS=4`, `CNN_MEASURE=1`, `MORPHEUS_TIMING=1`, `CNN_SELECTED_COMPACT=1`, `CNN_SELECTED_RUN_ADMITTED=1`, `CNN_BATCH` to 1/4/16, `CNN_CONV_MODE=default`, `CNN_PROVE` to that directory, and optionally `CNN_FIXTURE` to the newly generated fixture. Start from a minimal environment (PATH, HOME and LANG plus the listed variables) to avoid unrelated protocol overrides. Enforce a 3 GiB address-space ceiling; the recorded runner also required at least 3.5 GiB available memory, 512 MiB free temporary space, and twice the logical response bytes plus 512 MiB free output space. These are resource admission checks, not cryptographic checks. Do not set `MORPHEUS_COIN_SEED` for selected runs. The fourth predeclared case is batch4 with `CNN_CONV_MODE=pp`; its owner proof/verifier suite and the independent public-only replay passed.

Pin the public registry on close before the proof exists. Run a fresh verifier process with `CNN_VERIFY` set to the output directory, `CNN_SELECTED_COMPACT=1`, `RAYON_NUM_THREADS=4`, `CNN_MEASURE=1` and `MORPHEUS_TIMING=1`, and `CNN_FIXTURE` set to a nonexistent path. `CNN_SELECTED_RUN_ADMITTED`, `CNN_BATCH` and `CNN_CONV_MODE` are not needed by verification: batch/mode are reconstructed from the canonical registry. Do not provide fixture/secret material; retain all isolated negative-control results. Public verification uses the same implementation in a separate process, not a second cryptographic implementation. Registry pinning is essential: a proof's own chosen registry is not an external model/input commitment.

Preparing the publication files did not regenerate the fixture or proofs. Separately recorded standard-Cargo CPU build and saved-wire correctness checks are summarized above; no new benchmark is claimed. The independent evidence audit is complete. Default-CUDA compile/link validation also passed for bench_streaming_lenet, morpheus_trained_digits and morpheus_trained_cnn against the same frozen source. This is compile/link compatibility only: the CNN workload harness intentionally runs in CPU-replay mode and rejects CUDA execution. No GPU driver, GPU proof or GPU performance measurement was used.
